## 📅 Session 09:00 - OpenClaw(MoltBot) 소개 및 에이전트 기초

### 📌 강의 핵심 요약
이번 세션에서는 강의 실습을 위한 AI 에이전트 도구인 **OpenClaw(구 MoltBot)**의 설치 방법과 구조를 소개했습니다. 특히 LLM 모델(Claude 3 Opus, Sonnet, Haiku)별 비용과 성능 차이를 이해하고, 상황에 알맞은 모델을 선택하는 전략의 중요성을 강조했습니다. 또한 SSH를 통한 원격 제어와 멀티 에이전트(Multi-Force) 활용 가능성을 시연했습니다.

### 📚 상세 내용 정리

#### 개념 설명: LLM 모델 선택 전략
- **Claude 3 Opus**: 성능이 가장 뛰어나지만 비용이 높고 속도가 느림. 복잡한 추론이나 코딩에 적합.
- **Claude 3 Sonnet**: 성능과 비용의 균형이 잡힌 모델. 일반적인 작업에 추천.
- **Claude 3 Haiku**: 가장 빠르고 저렴함. 단순 반복 작업이나 빠른 응답이 필요할 때 효율적.
- **Tip**: 무조건 최고 사양(Opus)을 쓰는 것보다, 목적에 맞춰 Haiku나 Sonnet을 섞어 쓰는 것이 비용 효율적입니다.

#### 예시/실습 내용: OpenClaw 설치
- **설치 방법**: 터미널에서 원라인 커맨드(One-line Command)로 설치.
  ```bash
  # Mac/Linux 예시 (실제 명령어는 강의 자료 참조)
  curl -sL https://install.openclaw.example | bash
  ```
- **주요 기능**:
  - **원격 제어**: SSH를 통해 다른 PC(강의장 서버 등)에 접속하여 제어 가능.
  - **Context Sharing**: 링크드인(LinkedIn) 등의 계정 정보를 에이전트에 주입하여 맥락을 이해시킴.

#### 주의사항 또는 팁
- **토큰 비용 주의**: Opus 모델을 계속 켜두면 순식간에 토큰 비용이 발생할 수 있습니다. 사용하지 않을 때는 끄거나 저렴한 모델로 변경하세요.
- **보안**: SSH 접속 시 비밀번호 및 IP 관리에 유의해야 합니다.

## 📅 Session 10:00 - AI 에이전트(AI Agent)의 구조와 미래

### 📌 강의 핵심 요약
Chatbot을 넘어 행동하는 **AI Agent**의 4대 핵심 요소(Brain, Tool, Perception, Memory)를 심도 있게 다뤘습니다. 단순 검색이 아니라 실제 업무를 수행(Action)하는 에이전트의 구조와, 이를 뒷받침하는 핵심 기술인 **RAG(검색 증강 생성)**, **Function Calling**, **Orchestration**을 설명했습니다.

### 📚 상세 내용 정리

#### 개념 설명: AI 에이전트 아키텍처 (4 Pillars)
1. **Brain (두뇌)**: 의사결정 및 계획 수립 (LLM). 라우터(Router) 역할을 수행하여 적절한 도구를 선택함.
2. **Tool (도구)**: 실제 작업을 수행하는 능력 (웹 검색, 코드 실행, API 연동 등).
   - *중요*: 도구에는 명확한 **설명(Description)**과 **제약 조건(Limit)**을 부여해야 에이전트가 헷갈리지 않음.
3. **Perception (인식)**: 시각(Vision), 청각(Audio), 센서 등 멀티모달 입력 처리.
4. **Memory (기억)**: 단기 기억(Context Window) 및 장기 기억(Vector DB).

#### 기술 키워드 해설
- **RAG (Retrieval-Augmented Generation)**: 사내 문서나 비공개 데이터를 검색하여 LLM에 참고 자료로 제공하는 기술. '할루시네이션' 방지에 필수.
- **Function Calling**: 자연어 명령을 특정 함수(API) 실행을 위한 파라미터(JSON)로 변환하는 기술. (예: "내일 날씨 어때?" -> `get_weather(date='tomorrow')`)
- **MCP (Model Context Protocol)**: 다양한 데이터 소스를 연결하는 표준 프로토콜이나, 토큰 소모량이 많을 수 있어 주의 필요.

### 💡 핵심 포인트
- "AI에게 손발(Tool)을 달아주는 것이 에이전트의 핵심이다."
- RAG는 기업용 AI의 필수 조건이다. (우리 회사의 비밀 정보를 AI가 알게 하는 방법)

### 🔗 관련 키워드
- RAG, Function Calling, Vector DB, Orchestration, Context Window

## 📅 Session 11:00 - AI 시대의 커리어와 채용 트렌드

### 📌 강의 핵심 요약
카카오와 오늘의집 등 실제 채용 공고를 분석하며, 현업에서 원하는 **Agentic Workflow** 설계 능력에 대해 설명했습니다. 또한 단순 코딩 능력보다 전체 파이프라인을 설계하는 **기획력**이 중요해지고 있으며, 데이터베이스 트렌드가 Vector DB 전용 솔루션에서 **PostgreSQL(pgvector)** 통합으로 회귀하고 있음을 짚었습니다.

### 📚 상세 내용 정리

#### 개념 설명: Agentic Workflow & Tools
- **Agentic Workflow**: 단일 에이전트가 아닌, 기획자-개발자-리뷰어처럼 여러 에이전트가 협업하는 **Multi-Agent** 시스템 설계.
- **주요 프레임워크**:
  - **LangChain**: 가장 널리 쓰이지만 복잡함.
  - **CrewAI**: 롤플레잉(Role-playing) 방식의 협업 구조 설계에 용이함. (예: 선장, 요리사, 항해사 등 역할 부여)
  - **Autogen**: MS에서 개발한 멀티 에이전트 프레임워크.

#### 시장 트렌드: DB의 회귀
- **Vector DB**: Pinecone, Chroma 등이 유행했으나, 관리 포인트 증가로 부담.
- **PostgreSQL + pgvector**: 기존 RDBMS(PostgreSQL)에 벡터 기능을 추가하여 통합 관리하는 것이 대세. (OpenAI도 내부적으로 사용)

#### 주의사항 또는 팁
- **포트폴리오 조언**: "공부했다"가 아니라 "**무엇을 해결했는가**"를 적어야 합니다. (예: "매일 아침 뉴스 요약 봇을 만들어 팀에 배포")
- 문과생/기획자에게 기회: 코딩 디테일보다 **워크플로우 설계** 능력이 더 중요해지므로, 기획력이 강점이 될 수 있습니다.

### 💡 핵심 포인트
- "코딩은 AI가 한다. 사람은 **설계(Design)**를 해야 한다."
- 채용 시장은 이제 '사용할 줄 아는 사람'을 넘어 '구조를 설계할 줄 아는 사람'을 원합니다.

### 🔗 관련 키워드
- CrewAI, LangChain, PostgreSQL, pgvector, Multi-Agent System

## 📅 Session 13:00 - n8n(n8n) 입문과 자동화 실습 가이드

### 📌 강의 핵심 요약
노코드 자동화 툴 **n8n**의 장점(비용, 가시성)과 설치 방법을 다뤘습니다. Zapier나 Make 대비 **무료(Self-hosted)**로 사용할 수 있다는 강력한 이점을 강조하며, Docker를 활용한 설치법과 초보자를 위한 단계별 학습 로드맵(문서 읽기 -> AI 멘토링 -> 프로젝트)을 제시했습니다.

### � 상세 내용 정리

#### 개념 설명: Why n8n?
1. **압도적 가성비**: 설치형(Self-hosted)은 무료. 실행 횟수 제한이 없어 대량 처리 자동화에 유리함.
2. **시각적 디버깅**: 노드 간 데이터 흐름을 실시간으로 확인 가능하여, 오류 추적이 매우 쉬움.

#### 예시/실습 내용: 학습 및 설치 가이드
- **학습법**: 공식 Docs URL을 AI(ChatGPT, Perplexity)에게 주고 "이 문서 기반으로 알려줘"라고 질문하기.
- **추천 프로젝트**:
  1. **[Lv.1] 뉴스 요약 봇**: RSS 크롤링 -> 요약 -> 메신저 전송
  2. **[Lv.2] 엑셀 자동화**: 구글 시트 연동 -> 데이터 처리 -> 이메일 발송
  3. **[Lv.3] 개인 비서**: 캘린더/할일 브리핑 에이전트
- **설치 (Docker)**:
  ```bash
  docker run -it --rm --name n8n -p 5678:5678 -v ~/.n8n:/home/node/.n8n n8n/n8n
  ```
  - 저사양(라즈베리 파이 등)에서도 충분히 구동 가능.

#### 주의사항 또는 팁
- **보안**: Self-hosted 버전은 서버 관리가 본인 책임이므로 보안 설정에 유의해야 합니다. 자신이 없다면 n8n Cloud(유료/Trial) 사용 권장.
- **Start Small**: 처음부터 거창한 것을 만들지 말고, 아주 작은 기능부터 구현하며 기능을 붙여나가세요.

### 💡 핵심 포인트
- "자동화는 **만들면서 배우는 것(Learning by Doing)**이다."
- **n8n**은 개인과 스타트업이 비용 걱정 없이 자동화 시스템을 구축할 수 있는 최적의 도구입니다.
