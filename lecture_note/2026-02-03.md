## 📚 상세 내용 정리

### 1. AI Agent 아키텍처 및 설계 원칙
- **개념 설명**:
    - **Brain (LLM)**: 판단의 주체.
    - **Memory**: 대화 맥락 유지 (Window Buffer 등).
    - **Tools**: 외부 API 및 기능 호출.
    - **Perception**: 외부 입력을 받아들이는 통로.
- **예시/실습**: Mparent(n8n UI)를 통해 날씨 도구를 연결하고 성격(페르소나)을 부여한 Agent 구축.
- **팁**: 실생활의 페르소나(예: 오박사)를 차용하면 Agent의 응답 일관성과 스토리텔링이 강화됨.

### 2. Structured Output 및 데이터 엔지니어링
- **개념 설명**: AI의 답변을 예측 가능한 JSON 형식으로 고정하는 Output Parser의 중요성.
- **예시/실습**: PokeAPI `/pokemon?limit=1350`을 호출하여 대량의 데이터를 수집하고, `Split Out` 노드를 통해 개별 아이템으로 분리 및 정제.
- **주의사항**: 고성능 모델(GPT-4 등) 사용 시 토큰 비용(Token Economy)을 고려하여 프롬프트를 최적화해야 함.

### 3. 데이터 시각화 및 리포팅 자동화
- **개념 설명**: QuickChart.js를 활용하여 코드 없이 URL 파라미터만으로 차트 이미지 생성.
- **예시/실습**: 수집된 포켓몬 타입을 속성별로 집계(Count)하여 막대 차트를 생성하고, 분석 결과와 함께 Slack/Email로 발송.
- **팁**: 단순 데이터 전송이 아닌, 분석 결과에 '이유'를 담아 리포트의 가치를 높여야 함.

### 4. 접근성 및 디자인 시스템
- **개념 설명**: 정보 취약계층을 고려한 웹 접근성(A11y)과 일관된 UX를 위한 디자인 시스템의 필요성.
- **실습 내용**: 색맹 사용자를 배려한 컬러 팔레트 활용 사례 및 의미 있는 디자인 구성 방안 논의.

## 💡 핵심 포인트
- **Problem Solving**: 특정 도구에 얽매이지 않고 API, SDK, 노코드 툴 등을 적재적소에 융합하는 능력이 중요.
- **Webhook의 가치**: Pull 방식(Polling)이 아닌 Push 방식(Webhook)을 통해 시스템 간 실시간 동기화 파이프라인 구축 가능.
- **포트폴리오 전략**: 남들이 하지 않는 독특한 주제(예: 응급실 뺑뺑이 데이터 분석, 포켓몬 데이터 분석 등)를 딥하게 파고들어 눈에 띄게 구성할 것.
